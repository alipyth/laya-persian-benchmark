# بنچمارک فارسی Laya — راهنمای قدم‌به‌قدم

[English](README.md)

این پوشه یه بنچمارک کامل و آماده‌ی اجراست. کارش اینه که نشون بده Laya پیام‌های پشتیبانی فارسی رو چقدر درست دسته‌بندی می‌کنه.

- **داده:** ۶۴ پیام مصنوعی
- **خانواده‌ها:** ۸ خانواده، مثل رسمی، محاوره، فینگلیش، نیم‌فاصله، منفی‌سازی و کنایه
- **برچسب‌ها:** ۴ برچسب متوازن: `billing` (مالی)، `technical` (فنی)، `cancel` (لغو) و `other` (سایر)

---

## ۱. نصب

پایتون ۳.۱۰ یا جدیدتر لازمه.

```bash
cd persian_fa
python -m venv .venv
# ویندوز:          .venv\Scripts\activate
# مک یا لینوکس:    source .venv/bin/activate
pip install -r requirements.txt
```

## ۲. بررسی بدون مدل

این مرحله نه اینترنت می‌خواد، نه GPU:

```bash
python audit.py
python -m unittest discover -s tests -v
```

باید `audit OK` و `OK` ببینی. هشدار `reviewed_by is TODO` طبیعیه (توضیحش در بخش ۵).

## ۳. تست کوتاه با مدل واقعی

بار اول حدود ۷۰۰ مگابایت از Hugging Face دانلود می‌شه:

```bash
python run.py --backend laya --checkpoint multilingual --limit 2 --repeats 1 --modes choice_fa --output runs/smoke
python audit.py --run-dir runs/smoke
```

## ۴. اجرای کامل

```bash
python run_all.py            # اگه کارت گرافیک NVIDIA داری:  --device cuda   |   مک M1/M2/M3:  --device mps
```

این دستور سه اجرا انجام می‌ده:
- `multilingual`
- `multilingual` با نرمال‌سازی فارسی
- `english`

هر کدوم با ۲ حالت پرامپت (فارسی و انگلیسی) و ۳ بار تکرار. روی CPU لپ‌تاپ حدوداً ۲۰ تا ۶۰ دقیقه طول می‌کشه.

خروجی توی `runs/<تاریخ>/` ذخیره می‌شه:
- `summary.md` برای هر اجرا
- `comparison_choice_fa.md` و `comparison_choice_en.md` برای مقایسه‌ی خانواده‌به‌خانواده

**چیزهایی که توی نتایج دنبالشون بگرد:**
- **`false cancel`:** چند بار مدل پیامی رو «لغو» تشخیص داده که لغو نبوده. توی یه سیستم واقعی، این یعنی بستن اشتباهی حساب یه نفر.
- **خانواده‌ی `negation`:** Laya روی منفی‌سازی ضعف شناخته‌شده داره.
- **فارسی در برابر انگلیسی:** آیا پرامپت فارسی بدتر از پرامپت انگلیسیه؟
- **اثر نرمال‌سازی:** آیا نرمال‌سازی خانواده‌های `orthography` و `digits` رو بهتر می‌کنه؟

## ۵. قبل از انتشار (خیلی مهم)

1. **همه‌ی ۶۴ پیام رو خودت بخون.** فایلش `data/cases.jsonl` هست. این پیام‌ها با کمک هوش مصنوعی نوشته شدن و باید یه فارسی‌زبان تأییدشون کنه. هر متن یا برچسبی رو که قبول نداری عوض کن. بعد این دستور رو بزن تا هش‌ها به‌روز بشن:
   ```bash
   python tools/update_manifest.py
   ```
2. **اسم خودت رو ثبت کن.** توی `data/manifest.json` فیلد `reviewed_by` رو پر کن، مثلاً `"reviewed_by": "Your Name (native speaker), all 64 texts and labels"`. بعد دوباره `python audit.py` رو اجرا کن.
3. **بعد از بازبینی دیگه دست نزن.** بعد از این مرحله متن‌ها و پرامپت‌ها رو تغییر نده. اگه بعد از دیدن نتایج داده رو عوض کنی، بنچمارک دیگه صادقانه نیست.
4. **اجرای نهایی رو با نسخه‌ی ثابت انجام بده:**
   ```bash
   python run_all.py --revision <commit مدل روی Hugging Face>
   ```
   بعد خروجی‌ها رو در `results/v1/` کپی کن و جدول‌ها رو توی بخش Results فایل `README.md` بذار.
5. **اگه کسی کمک کنه، کار قوی‌تر می‌شه.** اگه دو نفر دیگه هم مستقل برچسب بزنن و میزان توافق رو گزارش کنی، کارت از بنچمارک چینی هم محکم‌تر می‌شه.

> دستور `--backend keyword` فقط برای تست خط لوله‌ست. کلیدواژه‌هاش با دیدن همین داده نوشته شدن، پس عددش رو **هیچ‌وقت** به‌عنوان baseline منتشر نکن.

## ۶. فرستادن به ریپوی اصلی Laya

1. **اول Issue باز کن.** متن آماده‌ش توی `docs/issue_draft.md` هست. صبر کن تا نگهدارنده جواب بده.
2. **ریپو رو fork کن** و این پوشه رو کپی کن در `research/benchmarks/persian_fa/`. پوشه‌ی `runs/` رو کپی نکن.
3. **یه تست نهایی توی ریشه‌ی ریپو بگیر:**
   ```bash
   python research/benchmarks/persian_fa/audit.py
   python -m unittest discover -s research/benchmarks/persian_fa/tests -v
   ```
4. **PR بفرست:** کوچیک و تمیز، با لینک Issue و خلاصه‌ی نتایج.

## ساختار فایل‌ها

| فایل | کار |
|---|---|
| `data/cases.jsonl` | ۶۴ پیام، برچسب، دلیل، خانواده و نوع تله |

| `normalize.py` | نرمال‌سازی فارسی (ی و ک، ارقام، نیم‌فاصله) |
| `run.py` | اجرای مدل و ثبت همه‌ی جواب‌های خام |
| `audit.py` | بررسی سلامت داده و اجرا و محاسبه‌ی دوباره‌ی نتایج |
| `compare.py` | جدول مقایسه‌ی چند اجرا |
| `run_all.py` | کل آزمایش با یک دستور |
| `tests/` | ۱۵ تست بدون مدل |
